DO YOU COPY?
Game Design Document
Status: Refined Core Design
Platform: PC-first
Target Runtime: 25-35 minutes
Genre: First-person radio operations horror / verification thriller


1. HIGH CONCEPT

Do You Copy? is a short first-person radio-operations horror game in which the player supports two field agents from a communications station.

Every important interaction asks the same question:

IS THE PERSON ON THIS CHANNEL REALLY WHO THEY CLAIM TO BE?

The player tunes into transmissions, checks the speaker against available evidence, optionally challenges them, then decides what instruction to send.

Something in the communications network is learning how the field team speaks, what they know, and how they authenticate themselves.

Eventually, the correct voice and the correct password are not enough.

Core fantasy:
"I am the person in the chair deciding which voice gets trusted."

Target experience:
A complete escalating scenario in roughly 30 minutes, not a campaign.


2. DESIGN PILLARS

2.1 TUNE -> VERIFY -> DECIDE

The game has one repeated loop:

TUNE
Find and clean the transmission.

VERIFY
Determine whether the speaker and message are credible.

DECIDE
Send an instruction or cut the route, then live with the consequence.

Every major mechanic must strengthen one of these three verbs.

If a feature creates a fourth parallel game, cut it.

2.2 Identity is the puzzle

There are no generic brain-training puzzles.

The puzzle is the caller.

Evidence can include:
- voice
- callsign
- assigned frequency
- last known location
- current task
- authentication response
- knowledge from previous calls
- speech habits
- contradictions with another agent

No UI element gives a "real/fake" answer.

2.3 Establish rules, then corrupt them

The first minutes teach reliable procedures.

The ghost becomes frightening by learning and breaking those procedures.

Progression:
1. wrong or noisy information
2. impossible information
3. copied identity
4. copied authentication
5. station data itself becomes suspect

2.4 Decisions change later calls

Wrong decisions should normally continue the game.

Consequences are heard later:
- an agent reaches the wrong place
- an agent misses a rendezvous
- a route becomes unavailable
- a genuine caller no longer trusts the operator
- the ghost gains information or access

Avoid frequent game-over states.

2.5 One room, few systems, strong reuse

The room exists to make the operator fantasy physical.

Most content is:
- scripted voice
- changing screen data
- changing paper information
- state flags
- audio
- lighting

Do not create new environments to create new content.


3. PLAYER ROLE

The player is the communications operator for field team ECHO.

The field team consists of:

ECHO-ACTUAL
The disciplined team lead.

ECHO-2
A less formal second agent whose speech is easier to recognize.

The player never joins them physically.

The operator can:
- tune a frequency
- clean a signal
- inspect current records
- ask for authentication
- request a repeat
- tell an agent to HOLD
- tell an agent to PROCEED
- redirect an agent to one of a few known locations
- quarantine a channel

That is the complete gameplay vocabulary for the 30-minute version.


4. CORE LOOP

A normal contact should take roughly 45-120 seconds.

4.1 TUNE

A signal appears on the spectrum display and in the radio audio.

The player:
- turns the frequency dial
- uses fine tune if necessary
- adjusts one signal-quality control

For the initial version, use only:

FREQUENCY
Find the carrier.

SQUELCH OR GAIN
Make the voice intelligible.

Do not ship a full radio simulator with gain, squelch, bandwidth, notch, AGC, antenna selection, and multiple receiver banks.

The interaction must become fast once learned.

Target:
A practiced player acquires a normal signal in 5-10 seconds.

Tuning exists to make receiving a call tactile. It is not the main puzzle.

4.2 VERIFY

After acquisition, the player hears the report.

The workstation provides only the evidence needed to judge it:

SCREEN
- active frequency
- claimed callsign
- last verified location
- current objective
- recent communication log

PAPER
- authentication challenge sheet
- small frequency / assignment reference

MAP
- three or four field locations
- last confirmed position of each agent

The player can request:

REPEAT
Replay or repeat the key report.

AUTHENTICATE
Issue the current challenge.

The response becomes another piece of evidence, not proof.

The player is expected to remember some recent context, but the communication log should prevent the game from becoming a memory test.

4.3 DECIDE

The player gives one operational response.

Primary actions:

HOLD
Do not move. Await further verification.

PROCEED
Follow the requested/current route.

REROUTE
Select one alternate known location.

QUARANTINE CHANNEL
Permanently block the current route.

Do not use a generic TRUST / FAKE button.

The decision should be framed as something an operator would actually tell the field team.

4.4 CONSEQUENCE

The field simulation is a small state machine, not a strategy layer.

Track only:
- ECHO-ACTUAL location/status
- ECHO-2 location/status
- which channels are available
- which transmissions the ghost has overheard
- a few scenario flags

Consequences should reappear as future calls.


5. WORKSTATION AND GAMEPLAY LOCATIONS

The room is a compact communications room built in Blender.

Only a few objects need full interaction.

5.1 RADIO RECEIVER

Primary interaction:
- frequency dial
- one cleanup control
- channel indicator

Used in every contact.

5.2 SPECTRUM DISPLAY

Programmatically rendered.

Purpose:
- shows active carriers
- helps find frequencies
- later shows suspicious duplicate/impossible signals

The spectrum display should be readable at a glance.

5.3 TERMINAL

Programmatically rendered.

Contains:
- current contact
- callsign records
- last verified location
- recent communication log
- simple status updates

Do not build a large fake operating system.

5.4 PAPER REFERENCE

Physical authentication sheet and frequency list.

This gives the player one source of information that is separate from the computer.

Late in the game, disagreement between paper and terminal can matter.

5.5 FIELD MAP

Keep it extremely small:
- 3-4 named locations
- two agent markers
- route lines

The map is reference material, not a strategy minigame.

5.6 MICROPHONE / PUSH-TO-TALK

Used when sending the selected response.

The hand moving to the microphone gives the final decision physical weight.

5.7 CHANNEL QUARANTINE CONTROL

A protected switch/button used only after the mechanic is introduced.

It should look more consequential than ordinary controls.

5.8 NON-CORE PROPS

Printer, patch board, door, shelves, filing cabinets, lights, and room clutter may exist visually.

They do not need gameplay unless a scripted moment specifically requires them.

Do not turn every prop into a system.


6. IDENTITY VERIFICATION

Each agent has a compact identity model the player can actually learn within 30 minutes.

ECHO-ACTUAL

Traits:
- concise
- follows procedure
- expects read-back
- rarely uses contractions
- uses "Operator" before direct requests

ECHO-2

Traits:
- conversational
- occasionally jokes
- abbreviates locations
- sometimes talks before formally identifying himself

Verification evidence:

STATIC FACTS
- callsign
- primary frequency
- role

CURRENT FACTS
- last verified location
- current task
- latest route change

AUTHENTICATION
- current challenge-response

BEHAVIOR
- speech habits
- protocol habits

The ghost's progression is the gradual acquisition of these categories.

Important rule:
Authentication proves that the caller knows an answer. It does not prove identity.


7. AUTHENTICATION / RIDDLES

Retain riddles only as challenge-response authentication.

A challenge should take seconds, not minutes.

Example:

CHALLENGE DELTA-4
"What has keys but opens no locks?"

EXPECTED:
KEYBOARD

The player reads the challenge aloud through a button/action.
The caller responds.
The player compares the answer with the sheet.

Use approximately 4-6 challenge pairs in the whole game.

Progression:

EARLY
Real agents answer correctly. False/noisy calls fail.

MIDDLE
A suspicious caller provides an obsolete but once-valid answer.

LATE
The ghost provides the current correct answer because it heard the challenge used earlier.

FINAL
Authentication is no longer sufficient; context and contradiction matter more.


8. QUARANTINE / SACRIFICE

The irreversible sacrifice mechanic is:

QUARANTINE CHANNEL

When used:
- the current frequency/route is permanently blocked at the station
- all future transmissions assigned to that route are lost
- the ghost cannot use that route again
- a real agent may lose their primary contact path

Each agent has only limited communication redundancy.

Therefore quarantining a channel is not a "kill fake caller" button.

It trades uncertainty now for reduced communication options later.

For the 30-minute scenario, allow at most 2 meaningful quarantine opportunities.

Do not add separate sacrifice systems such as destroying databases, cutting power, abandoning routes, and disabling receiver banks. One irreversible mechanic is enough.


9. THE GHOST

The ghost should initially sound exactly like ordinary radio trouble.

Do not use an obvious demon filter.

Its progression during the scenario:

STAGE 1 - NOISE
- crosstalk
- drift
- partial identifier
- plausible equipment fault

STAGE 2 - CONTRADICTION
- wrong location with correct voice
- information an agent should not yet know
- impossible timing

STAGE 3 - COPY
- exact agent voice
- correct callsign
- believable report
- one contextual mistake

STAGE 4 - LEARNING
- correct current authentication
- copied speech habit
- knowledge acquired from earlier open transmissions

STAGE 5 - MACHINE
- terminal record changes
- spectrum shows a carrier on a quarantined channel
- paper and digital records disagree
- a transmission appears to originate from the station itself

Do not escalate primarily through visual jumpscares.
Escalate by making previously reliable evidence unreliable.


10. 30-MINUTE SCENARIO

The game should be written around approximately 8 major contacts.

The exact timing can flex, but the function of each contact should remain clear.

00:00-03:00 - TRAINING CONTACT

ECHO-ACTUAL performs a routine radio check.

Player learns:
- tune
- clean
- read screen
- authenticate
- PROCEED

Nothing threatening happens.

Purpose:
Teach the complete loop immediately.

03:00-06:00 - NORMAL ECHO-2

ECHO-2 reports from Location A.

Player uses the map and sends HOLD or PROCEED.

Establish ECHO-2's less formal speech.

Purpose:
Teach personality as evidence.

06:00-09:00 - FIRST DISCREPANCY

A weak call claims to be ECHO-2.

One fact is wrong:
- frequency
OR
- location
OR
- authentication response

The correct choice should be discoverable.

Purpose:
Teach that identity verification matters.

09:00-13:00 - CONSEQUENCE / ROUTE DECISION

The genuine agents report the result.

Player must route one agent between two locations using conflicting but still plausible information.

Purpose:
Show that operator decisions affect the field situation.

13:00-17:00 - DUPLICATE VOICE

Two transmissions claim to be ECHO-ACTUAL.

Both use the correct voice.

One passes static checks but contradicts recent context.

Purpose:
Reveal the central horror mechanic.

17:00-21:00 - OBSOLETE AUTHENTICATION

A suspicious transmission answers an authentication challenge with a valid answer from an older sheet or earlier call.

Purpose:
Break the player's belief that authentication is definitive.

Introduce QUARANTINE CHANNEL after this contact.

21:00-26:00 - LEARNED COPY

The ghost now:
- uses the correct voice
- uses the current frequency
- answers the current challenge
- imitates one speech habit

The player must identify it through contextual contradiction or through comparison with the other agent.

This is the hardest normal verification event.

26:00-30:00 - FINAL CONTACT

The communications picture collapses.

At least one trusted source is contradicted:
- terminal vs paper
- map vs agent report
- quarantined route vs live carrier

The player must make one final operational decision:
- trust one agent
- hold/sever communication
- quarantine the remaining suspicious route

The ending is determined by accumulated decisions and surviving contact paths.

The finale should be playable, not a dialogue choice detached from the preceding mechanics.


11. BRANCHING AND ENDINGS

Keep branching shallow enough to author and test.

Each major decision should set flags that alter later dialogue and availability.

Do not create a fully branching narrative tree.

Recommended model:
A mostly shared sequence with conditional lines and state.

Track:
- ECHO-ACTUAL reachable: yes/no
- ECHO-2 reachable: yes/no
- ECHO-ACTUAL trusted at key moment: yes/no
- ECHO-2 trusted at key moment: yes/no
- channel A quarantined: yes/no
- channel B quarantined: yes/no
- ghost access level: low/high

Possible outcome families:

CONTAINED
The operator preserves enough genuine communication while isolating the ghost.

ISOLATED
The operator stops the ghost but loses contact with one or both agents.

OPEN LINE
The operator trusts the imitation at a critical moment and leaves a route open.

Do not build more than 3 ending families for the first version.


12. ROOM AND VISUAL DIRECTION

The room can be remote, institutional, functional, and mildly unsettling.

It does not need to satisfy the discarded "setting not fit for horror" constraint.

Production goals:
- simple geometry
- basic materials/colors
- limited asset count
- readable workstation silhouette
- strong lighting
- CRT/terminal graphics generated in code
- almost no decorative modeling that does not improve framing

Player movement:
Seated or tightly constrained around the desk.

The player should be able to look between:
- radio
- main display
- terminal
- paper
- map
- microphone
- quarantine control

These objects form the game's physical navigation loop.


13. PLAYER BODY AND INPUT

Use one rigged arm.

Arm interactions worth animating:
- turn main radio dial
- adjust cleanup control
- press authentication / response controls
- move to push-to-talk microphone
- activate quarantine switch

Do not animate bespoke hand motions for every desk prop.

Controls:

MOUSE
Look.

LEFT MOUSE
Interact / drag focused control.

MOUSE WHEEL
Fine tune radio.

KEYBOARD
Terminal shortcuts if useful.

PUSH-TO-TALK / CONFIRM KEY
Send selected operational response.

The player should feel faster at the station after five minutes of play.


14. AUDIO

Audio is a primary gameplay channel.

Each agent requires:
- stable voice identity
- clear speech habits
- consistent radio treatment

TTS is acceptable for authored lines if the result is intelligible and consistent.

Suggested processing:

VOICE
-> band limiting
-> compression
-> light saturation
-> static/noise
-> signal-strength degradation
-> occasional dropout

Signal degradation must never make required evidence unfairly unintelligible.

If a critical word is obscured, the player must be able to request REPEAT.

The ghost should use the copied agent's normal voice treatment.

Do not reveal identity through horror effects.


15. CONTENT BUDGET

Target content for the complete 30-minute version:

ROOM
- 1 environment

CHARACTERS
- 2 field-agent voices
- 1 ghost using copied voices

LOCATIONS
- 3-4 field locations

CONTACTS
- approximately 8 major contacts
- a few short incidental/static events

AUTHENTICATION
- 4-6 challenge-response pairs

PLAYER DECISIONS
- approximately 5 consequential decisions
- 1-2 quarantine opportunities

ENDINGS
- 3 outcome families

INTERACTIVE OBJECTS
- radio
- spectrum display
- terminal
- papers
- map
- microphone/PTT
- quarantine control

Anything beyond this budget requires replacing something else.


16. DEVELOPMENT PRIORITIES

P0 - 5-MINUTE PROTOTYPE

Build:
- room blockout
- radio tuning
- one cleanup control
- spectrum display
- one ECHO-ACTUAL voice
- authentication sheet
- HOLD / PROCEED
- consequence line

Success criterion:
The full Tune -> Verify -> Decide loop is understandable without explanation after one guided contact.

P1 - 10-MINUTE HORROR SLICE

Add:
- ECHO-2
- first false transmission
- contextual contradiction
- communication log
- duplicate voice

Success criterion:
The player can identify a fake using evidence rather than guessing from audio effects.

P2 - COMPLETE 30-MINUTE SCRIPT

Add:
- all 8 contacts
- quarantine mechanic
- branch flags
- final contact
- 3 ending families

P3 - POLISH

Prioritize:
- voice clarity
- radio feel
- interaction speed
- readable screens
- lighting
- pacing
- save/restart flow
- build stability

Do not spend polish time on non-interactive room clutter before the full scenario is playable.


17. CUT LIST

Cut from the current scope unless the core game proves it needs them:

- third field agent
- multiple receiver banks
- full radio simulation
- patch-panel minigame
- router puzzle
- resource economy
- security/threat percentages
- procedural signal generation
- generic cipher puzzles
- complex tactical map
- free exploration
- inventory
- combat
- dynamic AI dialogue
- large branching narrative tree
- high scores

These are expansion ideas, not requirements for Do You Copy?'s core experience.


18. DESIGN RULES

- Every contact must end in a decision or meaningful discovery.
- Tuning should take seconds, not become busywork.
- Identity is inferred from evidence.
- Never show a fake-caller probability.
- Authentication proves knowledge, not identity.
- The ghost learns before it breaks a rule.
- Wrong decisions should usually continue the story.
- Consequences should return through later calls.
- The communication log prevents accidental memory-test difficulty.
- Keep only two agents until the complete scenario works.
- Use one sacrifice mechanic.
- Reuse the same workstation in progressively less trustworthy ways.
- The final decision must use skills taught in the first five minutes.
- If a mechanic cannot pay off within 30 minutes, remove it.
